Foundational Concepts

Understanding the 8-Puzzle Problem

The 8-puzzle is a benchmark problem in Artificial Intelligence used to study how search algorithms navigate state spaces to reach a defined goal.

01

The Board & Tiles

A 3×3 grid containing eight numbered tiles (1 to 8) and a single blank space. The objective is to rearrange the tiles from an initial configuration into a target goal order.

02

Valid Tile Moves

Tiles cannot jump over each other. At each step, only a tile directly adjacent to the blank space can slide into the empty spot (corresponding to moving the blank Up, Down, Left, or Right).

03

Search Complexity

With 9 tiles, there are 9! = 362,880 possible arrangements. Finding the shortest move sequence without exploring redundant states or getting trapped in cycles requires systematic state-space search.

04

Solvability & Inversion Parity

Not all configurations can reach every goal. An inversion occurs whenever a larger number precedes a smaller one. Because sliding a tile preserves inversion parity, a puzzle is solvable if and only if initial and goal states share the same parity.

Assigned BFS Optimality

BFS is guaranteed to find the shortest move sequence because all step costs are uniform (c = 1). Its trade-off is high memory consumption: every node on the frontier must remain in memory until visited.

DFS vs. DLS vs. IDDLS

Standard DFS explores deep paths first and frequently produces non-optimal solutions. DLS restricts exploration to a depth cutoff. IDDLS re-runs DLS with incremental depths, combining the low linear memory of DFS with the completeness and optimality of BFS.

Informed Search Efficiency

A* with Manhattan Distance drastically prunes unpromising search branches, visiting far fewer nodes than uninformed search while guaranteeing mathematical optimality with an admissible heuristic.

1. Breadth-First Search (BFS)

Allotted: 24BDS0004 Optimal Complete ▾

Description & Concept

Breadth-First Search is the quintessential uninformed search strategy. It systematically explores the state space level-by-level, ensuring that every node at search depth d is expanded before any node at depth d + 1 is examined. In our implementation for registration 24BDS0004, it manages a First-In-First-Out (FIFO) queue and an explored hash set.

Working Principle (Step-by-Step)

  1. Initialize a FIFO queue with the root node representing the initial 8-puzzle board configuration.
  2. Add the initial state string to the visited set (hash set) to prevent cyclical transitions.
  3. Dequeue the node from the front of the queue and verify if it matches the target goal state.
  4. Generate all valid successor states by sliding the blank tile Up, Down, Left, or Right into adjacent positions.
  5. For each successor not yet in the visited set or queue, add it to the back of the queue with depth incremented by 1.
  6. Repeat until the goal configuration is reached or the queue is exhausted.

Advantages & Strengths

  • Guaranteed Shortest Path: Finds the minimal number of tile moves required to solve the puzzle because all transitions have unit cost (c = 1).
  • Cycle Immune: Explored hash table ensures it never gets trapped in infinite cyclical loops.

Limitations & Trade-offs

  • Exponential Memory Footprint: Keeps every generated node in memory, making it practical only for moderate solution depths (d ≤ 15 on browser runtimes).

Theoretical Properties

Data Structure FIFO Queue
Time Complexity O(b^d)
Space Complexity O(b^d)
Completeness Complete (finite b)
Optimality Optimal (for c = 1)
Branching Factor b ≈ 2.67
Goal Test Timing On Node Generation
Uninformed Search

2. Depth-First Search (DFS)

Linear Space Non-Optimal ▾

Description & Concept

Depth-First Search explores state branches as deeply as possible before backtracking. By always choosing the deepest unexpanded node, it aggressively moves down a single line of state transitions using a Last-In-First-Out (LIFO) stack.

Working Principle

  1. Push the initial puzzle state onto the LIFO stack.
  2. Pop the top node from the stack. If it matches the goal, return the solution path.
  3. Generate all valid sliding movements and push unvisited children onto the stack.
  4. Backtrack when a leaf node or dead-end is reached.

Advantages & Limitations

Advantage: Exceptional space efficiency O(b • m). Only requires memory proportional to the maximum search depth rather than the total number of nodes.
Limitation: In an 8-puzzle with cycles, DFS can wander down arbitrarily long, sub-optimal paths before backtracking, producing solutions with excessive moves.

Theoretical Properties

Data Structure LIFO Stack
Time Complexity O(b^m)
Space Complexity O(b • m)
Completeness Finite spaces only
Optimality Non-Optimal
Bounded Search

3. Depth-Limited Search (DLS)

Bounded Limit l Non-Optimal ▾

Description & Concept

Depth-Limited Search addresses the infinite-loop pitfall of DFS by enforcing a hard depth cutoff limit l. Any node whose path depth equals l is treated as a leaf node without children, preventing the search from descending deeper.

Working Principle

  1. Perform recursive or stack-based DFS starting from the initial state.
  2. Check current node depth against depth limit l.
  3. If depth ≥ l, record a cutoff and terminate that branch.
  4. If depth < l, expand successors and proceed recursively.

Advantages & Limitations

Advantage: Guarantees termination even in infinite or highly cyclical state graphs.
Limitation: If the shallowest goal state lies at depth d > l, the search fails to find a solution (incomplete).

Theoretical Properties

Data Structure Stack / Recursion
Time Complexity O(b^l)
Space Complexity O(b • l)
Completeness Incomplete if d > l
Optimality Non-Optimal
Iterative Uninformed Search

4. Iterative Deepening Search (IDDLS)

Optimal Complete ▾

Description & Concept

Iterative Deepening Search combines the space efficiency of DFS with the completeness and optimality of BFS. It repeatedly executes Depth-Limited Search with gradually increasing depth limits (limit = 0, 1, 2, ... d) until a solution is found.

Working Principle & Overhead Analysis

While it appears wasteful to re-expand the top levels of the search tree repeatedly, the vast majority of nodes in an exponential tree reside in the bottom level. The overhead is bounded by:

Nodes = Σ (d - i + 1) b^i ≤ O(b^d)

For an 8-puzzle with b ≈ 3, the overhead is only about 33% more node generations than BFS, while operating in linear O(b • d) memory.

Theoretical Properties

Data Structure Iterative Stack
Time Complexity O(b^d)
Space Complexity O(b • d) [Linear]
Completeness Complete
Optimality Optimal (for c = 1)
Informed Heuristic Search

5. Greedy Best-First Search (GBFS)

Fast Exploration Non-Optimal ▾

Description & Concept

Greedy Best-First Search attempts to minimize the estimated distance to the goal by ordering its priority queue strictly by the heuristic function: f(n) = h(n). It expands the node that appears physically closest to the target goal regardless of how many moves were already taken to reach it.

Working Principle

  1. Calculate heuristic value h(root) and insert into a priority queue.
  2. Extract the node with the minimum h(n) value.
  3. If goal state reached, construct solution path.
  4. Compute heuristic for all child states and enqueue ordered by h.

Advantages & Limitations

Advantage: Typically reaches a solution with far fewer node expansions than uninformed search.
Limitation: Susceptible to heuristic local minima and dead-ends. Because it ignores past path cost g(n), it is not optimal and can take detour routes.

Theoretical Properties

Data Structure Min-Priority Queue
Evaluation Function f(n) = h(n)
Time Complexity O(b^m) worst case
Space Complexity O(b^m)
Completeness Complete in finite graphs
Optimality Non-Optimal
Optimal Informed Search

6. A* Search

Optimal Complete ▾

Description & Concept

A* Search is the gold standard for informed heuristic search. It combines historical path cost g(n) (number of moves made so far) with the estimated remaining distance to the goal h(n) through the total evaluation function:

f(n) = g(n) + h(n)

Optimality Conditions & Proof

A* tree search is optimal if h(n) is admissible (never overestimates the true remaining distance $h^*(n)$). Furthermore, A* graph search is optimal without reopening closed nodes if h(n) is consistent (monotonic):

h(n) ≤ c(n, a, n') + h(n')

Both Misplaced Tiles and Manhattan Distance satisfy admissibility and consistency on the 8-puzzle.

Theoretical Properties

Data Structure Min-Priority Queue
Evaluation Function f(n) = g(n) + h(n)
Time Complexity Sub-exponential (pruned)
Space Complexity O(b^d)
Completeness Complete
Optimality Optimal (Admissible h)
Heuristic Formulations • Mathematical Analysis

Heuristic Metrics & Dominance Theorem

Admissible Dominance: h2 ≥ h1 ▾

1. Misplaced Tiles: h1(n)

Measures the number of tiles that are currently not located in their target goal positions. The blank space is excluded from the count.

h1(n) = Σ [state[i] ≠ goal[i] ∧ state[i] ≠ 0]

Admissibility Proof: Any tile not in its goal position must be moved at least once. Since a single move can put at most one tile into its correct position, h1(n) never overestimates the true cost: $h1(n) \le h^*(n)$.

2. Manhattan Distance: h2(n)

Calculates the sum of vertical and horizontal grid steps every tile must traverse to reach its target goal slot.

h2(n) = Σ (|row(i) - target_row(i)| + |col(i) - target_col(i)|)

Dominance Theorem: For any 8-puzzle board configuration $n$, every misplaced tile requires at least 1 move, while Manhattan distance measures the exact coordinate distance without obstacles. Hence:

h2(n) ≥ h1(n) for all states n

Because h2 strictly dominates h1, A* with Manhattan Distance expands equal or strictly fewer nodes than A* with Misplaced Tiles.
